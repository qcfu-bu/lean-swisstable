over repetitions (below 1: faster than the baseline). One op is one map call. load =
n / the final capacity of Std (and OAMap). Columns left of `|` give every pass its own
permutation or key set; the ones right of it (getd, getopt in insertion order,
reinsert, fold) repeat one pass by definition, and are marked * where a repetition
runs more than one pass (n < 5*10^5), so the branch predictor can learn the sequence.
Notes: getopt allocates a `some` per hit in Std (~2.5 ns each). Std's
getThenInsertIfNew? (hashcons) also allocates per hit. In-order lookups read Std's
chain cells in allocation order; the shuffled columns are the general case.
Erase workloads: erase-alt erases every other key (random order) of a fresh map per
pass; erase-alt-get looks up all n keys (shuffled, half of them erased); churn runs
iters*n rounds of insert-new + erase-oldest on a map of n keys (2 ops a round);
churn-get looks up its n live and n last-erased keys (shuffled); erase-all erases
every key of a fresh map per pass (random order).
