# SwissTable proof architecture: porting Std's HashMap and HashSet lemmas

Scope: the 678 theorems of `Std/Data/HashMap/Lemmas.lean` and the 320 of
`Std/Data/HashSet/Lemmas.lean` (Lean v4.35.0), restated for `SwissTable.HashMap α β` and
`SwissTable.HashSet α` with identical names, statements and attributes. The table layout is still
being chosen, so everything below assumes only an open-addressing table whose observable model
is its list of entries.

Files in this directory (all written for this study):

| file | what it is |
|---|---|
| `Mock.lean` | first experiment: 12 lemmas (the 8 requested + 4 siblings) under approach (a) |
| `Mock2.lean` | uniformity experiment: a list-backed mock with the full operation set the sample needs, the Layer 1 and 1.5 lemmas (41), `simp_to_model`, the 50 randomly sampled lemmas (34 HashMap, 16 HashSet), the 52 siblings they depend on, and 5 `at *` variants. 148 theorems, no `sorry`, axiom-clean |
| `Mock3.lean` | `Mock2.lean` plus approach (b): a transfer to `Std.ExtHashMap` and a `port` tactic that applies the `Std.ExtHashMap` lemma of the same name. 182 theorems, no `sorry` |
| `AutoPort.lean`, `AutoPort.log` | the 34 sampled HashMap lemmas with proofs generated by `tools/port.py` (no hand edits), compiled against the mock |
| `tools/port.py` | the porting script (Std statement + Std proof chain, renamed) |
| `tools/extract2.py`, `tools/chain.py` | extract every theorem of the Std files and follow each HashMap proof down to its `RawLemmas.lean` proof |
| `tools/auto_all.lean` | `port.py` run over all 678 HashMap lemmas (not compiled: the mock lacks some operations) |

Each `.lean` file is a single file importing `Std` (and `Lean` for `Mock3.lean`), checked with
`~/.elan/toolchains/leanprover--lean4---v4.35.0/bin/lean FILE`. All three mock files produce no
output, so no errors and no warnings. They take 0.4 s, 0.6 s and 0.9 s including the import.

## 1. Recommendation in one paragraph

Use Std's own architecture, collapsed to one layer. The table proves about 45 model lemmas
(Layer 1) that state each operation and query in terms of
`toListModel m : List ((_ : α) × β)`, using the vocabulary of `Std.Internal.List`. A copy of
Std's `simp_to_model` macro (Layer 2), with our lemma tables and a one-line discharger because our
map bundles its invariant, then proves the user-facing lemmas with Std's own `using` terms from
`DHashMap/Internal/RawLemmas.lean`. A script follows each Std proof chain and emits the port.
On a random sample of 50 lemmas, 47 port with no hand edit and compile against the mock, 2 need a
2-line hand proof, and 1 is a Layer 1 obligation. HashSet is Std's wrapper around
`HashMap α Unit`, and its 320 lemmas port verbatim (305 of them are a single term naming a
HashMap lemma). The transfer to `Std.ExtHashMap` (approach (b)) also works, and I built it, but
it covers at most 402 of the 678 statements. It cannot handle iteration, `isEmpty`, `Equiv` or
the lemmas without lawfulness hypotheses, and its own transfer lemmas need approach (a) first.
So it adds a layer without removing one, and I do not recommend it.

## 2. How Std proves its 678 lemmas

Std has four layers. Each layer above the bottom one is almost entirely one-line delegations.

1. `HashMap/Lemmas.lean` (678 theorems). 548 proofs are a single term naming a
   `DHashMap`/`DHashMap.Const` lemma (`getElem?_insert := DHashMap.Const.get?_insert`). Most of
   the rest are siblings (`get?_insert := getElem?_insert`, `by simp`), `rfl`, or `h.1.foo` for
   `Equiv`.
2. `DHashMap/Lemmas.lean` (964 theorems). These are `Raw₀.Const.get?_insert ⟨m.1, _⟩ m.2`
   (unbundle the invariant), or derived proofs such as `simp [← contains_iff_mem, contains_insert]`
   that turn `contains` statements into `∈` statements.
3. `DHashMap/Internal/RawLemmas.lean` (828 theorems, 631 `simp_to_model` calls). The typical
   proof is `simp_to_model [insert, Const.get?] using List.getValue?_insertEntry`. The macro
   rewrites every query to its list counterpart (`Const.get?_eq_getValue?`) and every operation
   under a query to its model up to permutation (it adds `getValue?_of_perm _ (toListModel_insert ..)`
   as a rewrite rule). It then `apply`s the list lemma and discharges the well-formedness side
   goals with `wf_trivial`.
4. `DHashMap/Internal/WF.lean` gives the model lemmas (`toListModel_insert : Perm (toListModel
   (m.insert a b).1.2) (insertEntry a b (toListModel m.1.2))`, `Const.get?_eq_getValue?`, …), and
   `Internal/List/Associative.lean` (1195 theorems, 10 382 lines) proves everything about the
   list operations.

Following each HashMap proof down the chain (`tools/chain.py`) gives these final proof shapes:

| final proof | count |
|---|---|
| a one-line `simp_to_model … using …` in RawLemmas | 257 |
| a 2–3 line `simp_to_model` (usually `revert h` first) in RawLemmas | 27 |
| a short non-`simp_to_model` RawLemmas proof (`simp [contains]`, sibling rewrites) | 102 |
| a long RawLemmas proof (insertMany induction, `any` via `forIn`) | 16 |
| derived at the DHashMap level from DHashMap siblings | 140 |
| derived at the HashMap level (siblings, `rfl`, `ext …`, `⟨…⟩`, `h.1.foo`) | 136 |

## 3. Our layering

```
Layer 0  the table (layout-specific)            Slots arrays, probe, grow, backward-shift erase
Layer 1  model interface (layout-specific)      ~45 lemmas: queries, iteration, ops, fused ops
Layer 1.5 generic derived ops (layout-free)     insertMany/ofList/union/inter/diff/beq via loops
Layer 2  user-facing HashMap lemmas             678 lemmas, simp_to_model + Std's using terms
         user-facing HashSet lemmas             320 lemmas, Std's text verbatim
```

Layers 2 and up use only Layer 1 statements, never the table. In the mock this is enforced by
making every implementation definition `@[irreducible]` before Layer 2 starts. So the bake-off
can swap layouts without touching Layers 2 and up. Std's Raw/Raw₀/DHashMap split disappears,
because we have no Raw variant (deferred) and our map bundles its invariant.

### The model type

`toListModel m : List ((_ : α) × β)`, a sigma list. This is exactly the type of Std's
`toListModel` for a `DHashMap α (fun _ => β)`, which gives three things:

* every `Std.Internal.List` operation and lemma used by the `Const` RawLemmas applies as is
  (`getValue?`, `insertEntry`, `eraseKey`, `Const.alterKey`, `insertListConst`, …);
* the user-facing `toList : List (α × β)` is stated as
  `m.toList = (toListModel m).map fun x => (x.1, x.2)`, exactly Std's
  `Raw.Const.toList_eq_toListModel_map`, so the bridging lemmas in the `using` terms
  (`List.foldl_eq_foldl_toProd`, `List.mem_map_toProd_iff_…`,
  `List.Const.map_insertEntry_perm_filter_map`) apply verbatim;
* `HashMap α Unit` has the model `List ((_ : α) × Unit)`, the type of
  `insertListIfNewUnit`, so `insertManyIfNewUnit` and HashSet need nothing extra.

A `List (α × β)` model would force every `using` term to be rewritten. The existing
`Wnetkat2/Data/OAMap` proofs use `List (α × β)` with `List.lookup`. The new Layer 1 restates
them for the sigma model; `getElem?_eq_lookup_toList` becomes `getElem?_eq_getValue?`, and
`distinct_keys_toList` becomes `DistinctKeys (toListModel m)`.

`toListModel` is proof-only (it is never run). The executable `toList`, `fold` and the other
iteration functions are free to be fast, but they must equal the model in the same order. See
section 9.

## 4. The Layer 1 lemma list

Notation: `l := toListModel m`. Each lemma is marked **U** (no hypotheses on `BEq`/`Hashable`)
or **L** (`[EquivBEq α] [LawfulHashable α]`, which is what our `WF.probe` invariant needs). The
U/L split is forced by Std, because the user lemmas that consume a model lemma are stated
without lawfulness exactly when it is marked U. Std's counterpart is in `WF.lean` unless noted.
The statements below are the ones the mock proves (`Mock2.lean`, `namespace Model`); the
`foldM`/`forM`/`forIn`/`toArray`/`values` ones follow the same pattern and are copied from
`WF.lean`.

**Invariant**

```lean
theorem distinctKeys [EquivBEq α] [LawfulHashable α] (m : HashMap α β) : DistinctKeys (toListModel m)  -- L (Raw.WFImp.distinct)
```

**Queries** (Std: `contains_eq_containsKey`, `Const.get?_eq_getValue?`, `getKey?_eq_getKey?`, …)

```lean

theorem isEmpty_eq_isEmpty (m) : m.isEmpty = (toListModel m).isEmpty                             -- U (L suffices)
theorem contains_eq_containsKey (m) {a} : m.contains a = containsKey a (toListModel m)            -- L
theorem mem_iff_containsKey (m) {a} : a ∈ m ↔ containsKey a (toListModel m) = true               -- L (from contains)
theorem getElem?_eq_getValue? (m) {a} : m[a]? = getValue? a (toListModel m)                       -- L
theorem getElem_eq_getValue (m) {a} {h : a ∈ m} :
    m[a]'h = getValue a (toListModel m) ((mem_iff_containsKey m).1 h)                             -- L
theorem getElem!_eq_getValue! [Inhabited β] (m) {a} : m[a]! = getValue! a (toListModel m)         -- L
theorem getD_eq_getValueD (m) {a fallback} : m.getD a fallback = getValueD a (toListModel m) fallback  -- L
theorem getKey?_eq_getKey? (m) {a} : m.getKey? a = List.getKey? a (toListModel m)                 -- L
theorem getKey_eq_getKey (m) {a} {h : a ∈ m} :
    m.getKey a h = List.getKey a (toListModel m) ((mem_iff_containsKey m).1 h)                    -- L
theorem getKey!_eq_getKey! [Inhabited α] (m) {a} : m.getKey! a = List.getKey! a (toListModel m)   -- L
theorem getKeyD_eq_getKeyD (m) {a fallback} : m.getKeyD a fallback = List.getKeyD a (toListModel m) fallback  -- L
```

`get?`, `get` and `get!` are defined so that `get? m a = m[a]?` is `rfl`, as in Std (the
`GetElem?` instance is `getElem? m a := m.get? a`).


**Iteration** (all U, all *equalities*: they fix every iteration function to the single model

`any_eq_any_toListModel` it is a one-liner.

**Operations** (Perm, so a table may reorder its slots on growth and deletion)

```lean

theorem toListModel_insertIfNew (m) {a b} : (toListModel (m.insertIfNew a b)).Perm (insertEntryIfNew a b (toListModel m))  -- L
theorem toListModel_erase (m) {a} : (toListModel (m.erase a)).Perm (eraseKey a (toListModel m))                    -- L
theorem toListModel_alter (m) {a} {f : Option β → Option β} :
    (toListModel (m.alter a f)).Perm (Const.alterKey a f (toListModel m))                                         -- L
theorem toListModel_modify (m) {a} {f : β → β} :
    (toListModel (m.modify a f)).Perm (Const.modifyKey a f (toListModel m))                                       -- L
theorem toListModel_filter (m) {f : α → β → Bool} :
    (toListModel (m.filter f)).Perm ((toListModel m).filter fun p => f p.1 p.2)                                   -- U
theorem toListModel_filterMap (m) {f : α → β → Option γ} :
    (toListModel (m.filterMap f)).Perm ((toListModel m).filterMap fun p => (f p.1 p.2).map (⟨p.1, ·⟩))          -- U
theorem toListModel_map (m) {f : α → β → γ} :
    (toListModel (m.map f)).Perm ((toListModel m).map fun p => ⟨p.1, f p.1 p.2⟩)                                 -- U
```

`insertEntry` replaces the stored key and value of an existing key (`replaceEntry`). This is
Std's semantics, and `getKey?_insert` says so (`… = if k == a then some k else …`). The earlier
`Wnetkat2/Data/OAMap` insert keeps the stored key, and it has to change.

and `fold`, as Std writes them. If the implementation fuses them, their lemmas move to Layer 1.

**Relations**

```lean
structure Equiv (m₁ m₂ : HashMap α β) : Prop where
  inner : (toListModel m₁).Perm (toListModel m₂)

theorem equiv_iff_toListModel_perm : m₁ ~m m₂ ↔ (toListModel m₁).Perm (toListModel m₂)        -- U
```

work unchanged.

That makes about 45 Layer 1 lemmas: 1 invariant, 12 queries, 4 empty-map queries, 11

are about Std's bucket internals, and we need none of those.

## 5. The tactic

This is Std's `simp_to_model` with four changes. The lemma tables are keyed by user-facing names
(`getElem?`, `mem`, …). The discharger is `apply Model.distinctKeys`, because the invariant is
bundled. `Bool.not_eq_true` is added, so `¬k ∈ m` becomes `containsKey k l = false`, which is
the normal form of the list lemmas. And it takes an optional `at *`, with a finisher for
hypotheses that cannot be rewritten in place. Verbatim from `Mock2.lean`:

```lean
open Lean in
meta def queryMap : Std.HashMap Name (Name × Array (MacroM (TSyntax `term))) :=
  .ofList
    [⟨`isEmpty, (``Model.isEmpty_eq_isEmpty, #[`(_root_.List.Perm.isEmpty_eq)])⟩,
     ⟨`contains, (``Model.contains_eq_containsKey, #[`(containsKey_of_perm)])⟩,
     ⟨`mem, (``Model.mem_iff_containsKey, #[`(containsKey_of_perm)])⟩,
     ⟨`size, (``Model.size_eq_length, #[`(_root_.List.Perm.length_eq)])⟩,
     ⟨`getElem?, (``Model.getElem?_eq_getValue?, #[`(getValue?_of_perm _)])⟩,
     ⟨`getElem, (``Model.getElem_eq_getValue, #[`(getValue_of_perm _)])⟩,
     ⟨`getElem!, (``Model.getElem!_eq_getValue!, #[`(getValue!_of_perm _)])⟩,
     ⟨`getD, (``Model.getD_eq_getValueD, #[`(getValueD_of_perm _)])⟩,
     ⟨`getKey?, (``Model.getKey?_eq_getKey?, #[`(getKey?_of_perm _)])⟩,
     ⟨`getKey, (``Model.getKey_eq_getKey, #[`(getKey_of_perm _)])⟩,
     ⟨`getKey!, (``Model.getKey!_eq_getKey!, #[`(getKey!_of_perm _)])⟩,
     ⟨`getKeyD, (``Model.getKeyD_eq_getKeyD, #[`(getKeyD_of_perm _)])⟩,
     ⟨`toList, (``Model.toList_eq_toListModel_map, #[])⟩,
     ⟨`keys, (``Model.keys_eq_keys_toListModel, #[])⟩,
     ⟨`fold, (``Model.fold_eq_foldl_toListModel, #[])⟩,
     ⟨`all, (``Model.all_eq_all_toListModel, #[])⟩,
     ⟨`any, (``Model.any_eq_any_toListModel, #[])⟩,
     ⟨`Equiv, (``Model.equiv_iff_toListModel_perm,
       #[`(_root_.List.Perm.congr_left), `(_root_.List.Perm.congr_right)])⟩]
     -- the real library adds values, toArray, keysArray, foldM, forM, forIn, beq

open Lean in
meta def modifyMap : Std.HashMap Name Name :=
  .ofList
    [⟨`insert, ``Model.toListModel_insert⟩, ⟨`insertIfNew, ``Model.toListModel_insertIfNew⟩,
     ⟨`erase, ``Model.toListModel_erase⟩, ⟨`filter, ``Model.toListModel_filter⟩,
     ⟨`filterMap, ``Model.toListModel_filterMap⟩, ⟨`map, ``Model.toListModel_map⟩,
     ⟨`alter, ``Model.toListModel_alter⟩, ⟨`modify, ``Model.toListModel_modify⟩,
     ⟨`union, ``Model.toListModel_union⟩, ⟨`inter, ``Model.toListModel_inter⟩,
     ⟨`diff, ``Model.toListModel_diff⟩, ⟨`insertMany, ``Model.toListModel_insertMany_list⟩,
     ⟨`insertManyIfNewUnit, ``Model.toListModel_insertManyIfNewUnit_list⟩]

macro "wf_trivial" : tactic => `(tactic| first | assumption | apply Model.distinctKeys)
macro "wf_finish" : tactic => `(tactic| first
  | wf_trivial
  | (simp only [Bool.not_eq_true, Model.mem_iff_containsKey] at *; assumption))

syntax "simp_to_model" (" [" (ident,*) "]")? (Lean.Parser.Tactic.location)? ("using" term)? : tactic

macro_rules
| `(tactic| simp_to_model $[[$names,*]]? $[$loc]? $[using $using?]?) => do
  let mut queryNames : Array Lean.Name := #[]
  let mut congrNames : Array Lean.Term := #[]
  if let some names := names then
    for query in names.getElems do
      let some (query, congr) := queryMap.get? query.getId | continue
      queryNames := queryNames.push query
      for c in congr do
        congrNames := congrNames.push (← c)
  if queryNames.isEmpty then
    for (q, c) in queryMap.valuesArray do
      queryNames := queryNames.push q
      for c' in c do
        congrNames := congrNames.push (← c')
  let mut congrModify : Array (Lean.TSyntax `term) := #[]
  if let some modifyNames := names then
    for modify in modifyNames.getElems.flatMap
        (fun n => modifyMap.get? (Lean.Syntax.getId n) |>.toArray) do
      for congr in congrNames do
        congrModify := congrModify.push (← `($congr:term ($(Lean.mkIdent modify) ..)))
  `(tactic|
    (simp (discharger := wf_trivial) only
      [Bool.not_eq_true, $[$(Array.map Lean.mkIdent queryNames ++ congrModify):term],*] $[$loc]?
     $[apply $(using?.toArray):term];*)
    <;> try wf_finish)
```

Std's version also handles `Raw`, `insertMany` on `Raw₀` and the `WF` side goals of every
operation (the `wf_trivial` list `Raw.WF.insert₀ | Raw.WF.erase₀ | …`). None of that is needed
here.

Typical ported proofs (all from `Mock2.lean`, all compiling):

```lean
theorem getElem?_insert [EquivBEq α] [LawfulHashable α] {k a : α} {v : β} :
    (m.insert k v)[a]? = if k == a then some v else m[a]? := by
  simp_to_model [insert, getElem?] using List.getValue?_insertEntry

theorem getElem_insert [EquivBEq α] [LawfulHashable α] {k a : α} {v : β} {h₁} :
    (m.insert k v)[a]'h₁ =
      if h₂ : k == a then v else m[a]'(mem_of_mem_insert h₁ (Bool.eq_false_iff.2 h₂)) := by
  simp_to_model [insert, getElem] using List.getValue_insertEntry

theorem size_erase [EquivBEq α] [LawfulHashable α] {k : α} :
    (m.erase k).size = if k ∈ m then m.size - 1 else m.size := by
  simp_to_model [erase, size, mem] using List.length_eraseKey

theorem toList_insert_perm [EquivBEq α] [LawfulHashable α] {k : α} {v : β} :
    (m.insert k v).toList.Perm (⟨k, v⟩ :: m.toList.filter (¬k == ·.1)) := by
  simp_to_model                                     -- Std's 4-line Raw₀ proof, one name changed
  apply List.Perm.trans <| List.Perm.map _ <| Model.toListModel_insert m
  apply List.Perm.trans <| List.Const.map_insertEntry_perm_filter_map _ _ (by wf_trivial)
  simp

theorem getElem?_filterMap [EquivBEq α] [LawfulHashable α] {f : α → β → Option γ} {k : α} :
    (m.filterMap f)[k]? = m[k]?.pbind (fun x h' =>
      f (m.getKey k (mem_iff_isSome_getElem?.mpr (Option.isSome_of_eq_some h'))) x) := by
  simp_to_model [filterMap, getKey, getElem?] using List.Const.getValue?_filterMap

theorem Equiv.insert [EquivBEq α] [LawfulHashable α] (k : α) (v : β) (h : m₁ ~m m₂) :
    m₁.insert k v ~m m₂.insert k v := by
  simp_to_model [Equiv, insert] using List.insertEntry_of_perm _ h.1

theorem getKey?_diff_of_not_mem_left [EquivBEq α] [LawfulHashable α] {k : α} (not_mem : k ∉ m₁) :
    (m₁ \ m₂).getKey? k = none := by
  simp_to_model [mem, getKey?, diff] at *
    using List.getKey?_filter_not_contains_map_fst_of_containsKey_eq_false_left
```

`fold_eq_foldl_toList`, `getKey?_insert` and `HashSet.contains_insert` are in `Mock.lean`, and
the remaining 140 or so ported lemmas are in `Mock2.lean`.

## 6. Porting recipe (implemented in `tools/port.py`)

For every lemma of `HashMap/Lemmas.lean`, keep Std's attributes and statement text unchanged.
Build the proof as follows:

1. If the HashMap proof does not mention `DHashMap`, copy it. It uses sibling lemmas with the
   same names, `rfl`, or `by simp`.
2. Otherwise follow it to the DHashMap lemma. If that proof does not mention `Raw₀`, copy it and
   rename DHashMap lemma names to HashMap names (`Const.get?_alter` → `getElem?_alter`). The
   rename map is built from Std's 548 delegation lines.
3. Otherwise follow it to the RawLemmas proof (also through `h.1.foo`, which goes to
   `DHashMap.Equiv.foo` and then to `Raw₀.foo_of_equiv`, and through DHashMap proofs of the form
   `rw [← contains_eq_false_iff_not_mem] at h; exact @Raw₀.X …`). If it is
   `[revert h;] simp_to_model [qs] using T`, or the `revert h; simp_to_model [qs]; intro h;
   apply T h` form, emit `simp_to_model [qs'] [at *] using T'`, where:
   * `qs'` renames the queries: `Const.get?`→`getElem?`, `Const.get`→`getElem`,
     `Const.get!`→`getElem!`, `Const.getD`→`getD`, `Const.toList`→`toList`,
     `Const.insertMany`→`insertMany`, `Const.insertManyIfNewUnit`→`insertManyIfNewUnit`,
     `Const.alter`→`alter`, `Const.modify`→`modify`, and `contains`→`contains, mem` (HashMap
     statements say `k ∈ m` where RawLemmas say `m.contains k`);
   * `at *` is added when the statement has hypotheses. Std's Raw₀ statements put them after
     the colon (or `revert` them), and ours are binders. It is left out when `T` mentions `h.1`,
     because rewriting an `Equiv` hypothesis into a `Perm` would break `h.1`;
   * `T'` renames Raw₀ siblings to HashMap names and drops their `_ h` (map, WF) arguments.
     `List.*` lemmas are unchanged.
4. Otherwise emit the RawLemmas text renamed as above, and check it by compiling.

`Mock2.lean` shows the result of this recipe applied by hand. `AutoPort.lean` is the script's
output for the 34 sampled HashMap lemmas, inserted unchanged into the mock. 31 of the 34
compile. The other 3 are `getThenInsertIfNew?_snd` (a Layer 1 obligation, emitted as `sorry`),
`mem_insertMany_of_mem` (Std threads `WF` through `insertMany_ind`; the bundled proof is
`insertMany_ind (motive := fun m => k ∈ m) m h fun _ _ _ h => mem_insert.2 (Or.inr h)`), and
`insertManyIfNewUnit_list_equiv_foldl` (2 lines from the Layer 1.5 lemma
`insertManyIfNewUnit_list_eq_foldl`). See `AutoPort.log`.

Run over all 678 lemmas (`tools/auto_all.lean`), the script produces:

| script outcome | count |
|---|---|
| one-line `simp_to_model … using …` | 360 (283 direct, 77 through an Equiv or DHashMap hop) |
| copied HashMap proof (sibling, `rfl`, `by simp`) | 76 |
| copied DHashMap proof with names renamed | 66 |
| renamed RawLemmas text, to be checked (3 of the 4 in the sample compiled) | 128 |
| flagged: no RawLemmas proof found | 48 |

The 48 flagged lemmas are 29 Layer 1/1.5 equalities (`insertMany_cons`, `ofList_*`,
`unitOfList_*`, `erase_empty*`, `*_snd`, `*_ind`), 13 `Equiv` constructions written `⟨…⟩` in Std
(for example `Equiv.union_congr` and `map_id_equiv`; each is `simp_to_model [Equiv, op] using
List.…_of_perm …`, so the script can be extended to them), and 6 lemmas whose statement contains
`haveI … :=` (the `getElem_alter` family), where the script splits statement and proof in the
wrong place.

Other details of a full port:

* Copy the non-theorem commands of the Lemmas files verbatim: `instance : LawfulGetElem …`,
  `instance : Std.Internal.PureForIn …`, `instance instTrans`, the `grind_pattern` lines,
  `attribute [simp] contains_eq_false_iff_not_mem`, and the section `variable`s (some sections
  fix `{m : HashMap α Unit}`). Also copy the `DecidableEquiv` instance.
* HashSet uses one DHashMap-only lemma (`DHashMap.mem_of_mem_insertIfNew'`), so we provide
  `SwissTable.HashMap.mem_of_mem_insertIfNew'` as an extra (non-Std) lemma.
* Keep Std's `@[cbv_opaque]` and `@[inline]` attributes on our definitions, and `@[cbv_eval]` on
  lemmas, so the `cbv` tactic sees the same API.

## 7. Approach (b): transfer to Std

`Mock3.lean` implements it. Define `absE m : Std.ExtHashMap α β := Std.ExtHashMap.ofList m.toList`.
Prove that queries commute with it (`(absE m)[a]? = m[a]?`, the same for `getKey?`, `contains`,
`∈`, `size`, `getElem`, `getKey`). Prove that operations commute up to equality, by extensionality
(`Std.ExtHashMap.ext_getKey_getElem?`) plus the Std and our query lemmas for that operation:
`absE (m.insert k v) = (absE m).insert k v`. Then a `port` tactic looks up the current
declaration name, rewrites the goal and hypotheses with the transfer lemmas, and runs
`exact Std.ExtHashMap.<same name>`:

```lean
macro "transfer" : tactic => `(tactic|
  simp only [getElem?_eq_absE, getKey?_eq_absE, contains_eq_absE, mem_iff_absE, size_eq_absE,
    getElem_eq_absE, getKey_eq_absE, absE_insert, absE_erase] at *)

elab "port" : tactic => do
  let some decl ← Term.getDeclName? | throwError "port: no declaration name"
  let suffix := decl.replacePrefix `Mock.HashMap.T .anonymous
  evalTactic (← `(tactic| (transfer; exact $(mkIdent (`Std.ExtHashMap ++ suffix)))))

theorem getElem_insert {k a : α} {v : β} {h₁} :
    (m.insert k v)[a]'h₁ =
      if h₂ : k == a then v else m[a]'(mem_of_mem_insert h₁ (Bool.eq_false_iff.2 h₂)) := by port
```

It works. `getElem?_insert`, `getKey?_insert`, `size_erase`, `size_insert`, `contains_insert`,
`getElem_insert` and `getKey_erase` (dependent, with proofs inside the statement) and
`getElem?_erase_self` all go through. It also fails where expected: `toList_insert_perm`,
`fold_eq_foldl_toList` and `isEmpty_insert` give "simp made no progress", because ExtHashMap has
no `toList` or `fold` and no lemma named `isEmpty_insert`.

Why it is not the recommendation:

* **Coverage.** 214 of the 678 HashMap names do not exist in `ExtHashMap`, and only 402 of the
  464 shared names have an identical statement after stripping attributes. ExtHashMap has no
  `toList`, `keys`, `values`, `toArray`, `fold`, `foldM`, `forM`, `forIn`, `all` or `any` lemmas
  (none of these functions is defined on a quotient), no `Equiv` (it is `=`), and no `isEmpty_*`
  lemmas (it says `m = ∅`). It has no `*_emptyWithCapacity` lemmas either (`emptyWithCapacity_eq`
  says it is `∅`). For HashSet, 117 of the 320 names are missing and 173 are identical.
* **Hypotheses.** Every ExtHashMap operation takes `[EquivBEq α] [LawfulHashable α]`, so none of
  the 126 HashMap lemmas without lawfulness (filter, map, filterMap, iteration, `Equiv.refl`, the
  empty map, `insertMany_cons`, …) can transfer.
* **It is built on (a).** Each `absE_op` lemma needs our `getKey?_op` and `getElem?_op`, and the
  query transfer needs `distinct_keys_toList`, `getElem?_eq_some_iff_exists_beq_and_mem_toList`,
  `mem_toList_iff_…`, `map_fst_toList_eq_keys`, `contains_keys` and `getKey?_congr`. In the mock
  the whole transfer section is 109 lines (13 helper `simp_to_model` lemmas, the transfer lemmas
  for 7 queries and 2 operations, the tactics and 8 test lemmas). A full version needs about 15 queries and 15 operations.
* **No saving per lemma.** Under (a) the per-lemma proof is already a generated one-liner. `port`
  saves only the `using` term, which the script copies anyway.

Transferring to `Std.HashMap` instead (with `abs m ~m (abs m).insert k v`) would bring back
toList, Equiv and isEmpty, but only up to `Equiv`. Then `simp` cannot push `abs` through nested
operations (`(abs ((m.insert k v).erase j))[a]?`) without a setoid-rewriting tactic, and
`toList (abs m)` is only a permutation of `toList m`, so `fold_eq_foldl_toList` and the other
order-sensitive lemmas still need the model.

One use of (b) remains: `port` could be a fallback in the porting script for lemmas whose
generated proof fails. The sample did not need it.

## 8. HashSet

Build it the way Std does: `structure HashSet (α) [BEq α] [Hashable α] where inner : HashMap α Unit`,
with each operation defined exactly as Std's wrapper: `insert m a := ⟨m.inner.insertIfNew a ()⟩`
(no replacement, as Std documents), `get? := getKey?`, `toList := m.inner.keys`,
`insertMany := insertManyIfNewUnit`, `ofList := unitOfList`, `Equiv` with field
`m₁.1.Equiv m₂.1`, and so on. Then `HashSet/Lemmas.lean` ports verbatim. 305 of its 320 proofs
are a single term naming a HashMap lemma (`contains_insert := HashMap.contains_insertIfNew`), 13
are short `by` blocks over HashMap lemmas, and 2 refer to internals: `DHashMap.mem_of_mem_insertIfNew'`
(see section 6) and the public `Std.Internal.ForIn.toList_eq_of_forIn_eq`. All 16 sampled
HashSet lemmas compile verbatim in `Mock2.lean` (the private `ext` lemma is copied too). HashSet
needs no tactic and no transfer of its own, because it inherits the HashMap lemmas.

The cost of this design is an `Array Unit` of values in every set: 8 bytes per slot, a store per
insert, and a copy on growth, though no probe reads it. If the benchmark shows that this
matters, a value-less set core has to restate Layer 1 over `List ((_ : α) × Unit)`. The HashSet
proofs would then be retargeted from `HashMap.foo` to the set core's `foo`, and those lemmas
would be the `HashMap α Unit` lemmas ported a second time by the same script, which costs
compute rather than work. I would start with the wrapper and measure first.

## 9. Constraints on the implementation (input to the layout bake-off)

These follow from Std's statements, not from the proof technique:

1. **One iteration order.** `toList`, `keys`, `values`, `toArray`, `keysArray`, `fold`, `foldM`,
   `forM`, `forIn`, `all` and `any` must all enumerate `toListModel` in the same order, because
   Std states `fold_eq_foldl_toList`, `map_fst_toList_eq_keys`, `toArray_toList` and similar as
   equalities. Std builds `toList` with `foldRev` and cons for this reason.
2. **No lawfulness for these:** `filter`, `filterMap`, `map` (Perm lemmas), the empty map's
   queries, all iteration, `Equiv`, the fused-operation equalities, `erase_emptyWithCapacity`,
   and `insertMany_cons` and its relatives. A `filter` that deletes by backward shift or
   rebuilds by reinsertion must preserve the entry multiset without the probe invariant. That
   holds for reinsertion that never compares keys (the existing `grow` does this:
   `toList_grow_perm` needs no `EquivBEq`).
3. **Definitional shape.** `insertMany`/`insertManyIfNewUnit` must be Std's subtype-carrying
   `for` loop over `insert`/`insertIfNew` (so `insertMany_ind` holds for every `ForIn` instance).
   `ofList l = insertMany ∅ l` with no presizing (the statements are equalities of maps),
   `unitOfList`, `ofArray` and `unitOfArray` follow the same pattern, and `∅ = emptyWithCapacity`.
   `beq` is Std's `size` check plus `all`/`get?`.
4. **Fused operations share code.** `(m.containsThenInsert k v).2 = m.insert k v` and
   `(getThenInsertIfNew? m k v).1 = m[k]?` are equalities without lawfulness. Define `insert` as
   the second component of the fused operation, or derive both from one probe-and-write core.
5. **`erase` of a missing key returns `m` itself**, so that `erase_emptyWithCapacity` is an
   equality. This is also the fast path.
6. **`insert` replaces the stored key** (`replaceEntry`). So do `modify` (`Const.modifyKey` is
   `replaceEntry a (f v)`) and `alter` when `f` returns `some` (`insertEntry`). `insertIfNew` and
   HashSet's `insert` keep it.
7. **No `Inhabited`.** `emptyWithCapacity` lemmas are unconditional and the API takes no
   `Inhabited`, so the layout must not need placeholder keys or values. That is a layout
   question, but Layer 0's invariant must accommodate it.
8. **Layer 1 query lemmas should not be `rfl` lemmas.** In the mock, query lemmas proved by `rfl`
   become dsimp lemmas. `simp_to_model` then rewrites an `if` condition without the `Decidable`
   instance, and `getKey!_alter` fails (`instDecidableEqBool (f m[k]?).isSome true` against the
   rewritten condition). A real table's query lemmas are not definitional. If one is (a stored
   `size`, say), give it a non-`rfl` proof, as the mock does with `Model.nr`.

## 11. Risks

* `Std.Internal.List` is internal, and its header says users should not rely on it. Its lemma
  names have been stable, and the lemma statements we copy change with each Lean release anyway.
  Pin to v4.35.0, and on upgrade rerun `port.py` against the new sources (both the statements
  and the `using` terms come from there).
* Some `using` terms rely on simp normal forms, such as `Bool.not_eq_true` and the `ite`
  condition shapes. These were stable across the 148 mock theorems, but the remaining
  "renamed RawLemmas text" lemmas (128) are only estimated.
* Layer 1 is the real work. About 25 layout-specific lemmas need actual proofs: insert with
  growth and key replacement, erase by backward shift, alter, modify, filter, filterMap and map
  without lawfulness, the 12 queries, the iteration equalities and the fused operations. The
  earlier `Wnetkat2/Data/OAMap` proofs (that map has since been deleted) cover the queries, insert (with the old keep-the-key
  semantics) and grow.
